# Disposition Reporting Skill · 简洁处置说明

## 任务
从 **Rule Engine 的结论 + Evidence Store + Risk Gate / RSA** 生成两种文本：

1. **内部填写版**：尽量 1–2 句，保留结论、身份关联/差异、风险事由和必要的不确定性。
2. **合规沟通版**：复用上述事实，增加申请/工单标识、礼貌复核请求和提供的复核链接。

## 硬约束
- 身份关联和风险严重度是两个独立维度；未能排除 ≠ 已确认同一人。
- 仅有来源标识的 LN 风险事件，表述为**“LN 记录载明”**或“事由：”，不得冒充独立来源鉴真。
- 大型/严重事件 + 至少可观察的身份关联，可以生成**疑似命中上报草稿**，但阈值为候选规则、需公司确认。
- 已获得强关联证据可停止无关调查，不应因地址不一致反复无效查找。
- 缺少合理调查线索：结束自动调查、记录证据不足；**默认不创建人工调查队列**。
- 任何对 LN 的提交、接受名单、商户放行、外部消息发送均不在此 Skill 权限内。
- 对身份或事件有反证时必须保留；任何未提供的事由、地域、日期、地址变更都不能编造。
- 全部证据来源应存储在 `disposition.source_refs`，简短业务文本中不必铺陈所有 URL 与查找过程。

## 可复现接口
`ln_agent.disposition.build_disposition(...)` 生成文案；`PolicyGuard.validate_disposition_draft(...)` 强制检查输出契约；`DecisionRouter.finish` 在返回 Decision 之前执行。

## 业务结论与技术状态

业务展示只使用 **未命中 / 疑似命中 / 命中**。技术路由（例如 `RESIDUAL_SUSPICION`）不得作为业务结论。证据不足或工具异常且尚无依据形成结论时，`business_conclusion=null`，不自动判未命中。全部结论仅是草稿，需按授权政策处置。
