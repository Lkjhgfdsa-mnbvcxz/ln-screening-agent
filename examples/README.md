# Synthetic examples

All cases and documents in this directory are fabricated for offline regression and demonstrations. **Do not substitute real merchant records in a public repository.**

- `case_true_link.json`: synthetic strong-identity-link case; still requires risk review.
- `case_false_positive.json`: synthetic credible DOB difference; exclusion candidate, not authorized clearance.
- `demo_case.json` + `research_fixtures.json`: multi-hit routing fixture.
- `document_case.json` + `document_manifest.json` + `documents/`: local document parsing fixture.
- `case_workbuddy_capture.json` + `workbuddy_capture_bundle.json`: **fully synthetic** replay of the two authorized-local WorkBuddy adapters (browser snapshot + in-session model extraction). Select `workbuddy_capture` in `python3 run.py web`, or see `replay.html`. No real merchant data.
- `workbuddy_capture_replay.json`: the **actual** 68-event stream emitted when the synthetic case above is run through the real engine. Embedded in [`replay.html`](../replay.html), regenerated by `python3 scripts/build_replay.py --tests 219`. Contains no real case id, subject, identifier, internal URL or business log.
- `demo_workbench_data.json`: the synthetic data behind the **checklist-level** public workbench [`demo.html`](../demo.html). 8 checklist subjects / 154 hits / 4 parallel workers, with per-hit progress, business conclusions, individual reasons and Qichacha-shaped subject profiles. Generated by `python3 scripts/build_demo.py`; identifiers, subjects, domains, profile values and reasons are fabricated. Schema 1.1 also records the concurrency model: 8 subjects start together, 4 workers per case, with separate wall clocks for serial execution, a shared 4-worker pool, and all cases starting together; single-hit cost and post-parallel amortised share are distinct fields. The Qichacha connector is used only as a **field schema** (no live query was made; the real-time call returned 402 insufficient credits), and the page states that 0 structured hits does not mean no risk.

Generate the paired report from the repository root:

```bash
python3 run.py demo --out examples/two_case_demo_report.json
```

Generated `*_report.json` outputs are ignored by Git to avoid committing runtime artifacts.
